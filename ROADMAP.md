# Development roadmap

Build one working vertical slice first, then add one enforceable guarantee at a time. `DESIGN.md` remains the specification; each increment below should be an independently reviewable change with observable acceptance criteria.

Use a local mock upstream from the beginning. It should capture forwarded requests and produce controlled responses, delayed SSE chunks, usage reports, and failures. This makes acceptance checks deterministic without spending real API credits.

## Contracts to resolve before implementation

- **Authoritative prompt — resolved in steps 2 and 5:** `system_prompt` is required at issuance and persisted verbatim. Chat injection prepends a fresh system message and removes only client system messages with exactly matching string content. Sentinels, names, and headers never suppress it; all other messages retain their order and fields.
- **Token quota — resolved in steps 8 and 9:** complete validated reports add known usage exactly once. Admission atomically escrows available tokens, then narrows to a transformed text-prompt byte bound plus constrained generation for every requested choice. Missing usage stays unknown and permanently consumes its full reservation in a separate unreported counter, including after restart. Text-only upstream compatibility assumptions and temporary admission denials are specified in `DESIGN.md`.
- **Lifecycle — admission contract resolved in step 4:** revoke, done, and expiry close admission without cancelling admitted work. First terminal state wins; same-target retries are idempotent. In-flight reservations remain until normal reconciliation, including after `/done`; no early refund or usage reset.
- **Routing:** use a method-and-path allowlist. `/v1/models` ordinarily needs `GET`, unlike chat and embeddings.
- **Request accounting — resolved in steps 6 and 9:** every admitted attempt permanently consumes one request before route/body validation, including blocked requests, missing keys, body-dependent budget rejections, upstream failures, cancellation, and restart. Invalid credentials, inactive jobs, pre-body quota denials, and failed admission transactions consume nothing. No refunds; final admission persists exhaustion and later attempts receive `429`. Monthly monetary spend still needs pricing data; token totals alone are insufficient.

## Implementation increments

Each increment delivers demonstrable behavior, not just scaffolding.

| Step | Deliverable | Acceptance check |
| --- | --- | --- |
| **1. Runnable service and mock upstream — complete** | Configuration loading, `/healthz`, graceful shutdown, and a local upstream fixture. | Start the service and call health; drive the fixture through ordinary and delayed responses. |
| **2. Job issuance and persistence — complete** | SQLite migrations, authenticated control plane over TLS, key-pool configuration, and `POST /v1/jobs`. Generate secure tokens; persist only hashes and the job's authoritative prompt. | Issue a job, inspect persisted state, restart the service, and verify the job survives. Reject unauthenticated issuance and unknown key IDs. |
| **3. First complete proxy request — complete** | Support non-streaming chat only: job-token authentication, active-state checks, exact route allowlisting, bounded request bodies, and upstream authorization replacement. Never retry automatically. | Issue a token and send a chat request. The mock sees the configured upstream credential, not the job token. Invalid tokens and forbidden routes never reach it. |
| **4. Complete job lifecycle — complete** | Expiry, revoke, and done transitions, including their interaction with requests already admitted. | Hold an upstream request open, revoke the job, verify that request finishes while subsequent requests fail. Exercise expiry and done across restart. |
| **5. Authoritative prompt injection — complete** | Inject the stored operator prompt using a deterministic rule; preserve permitted client messages without trusting their sentinel claims. Apply only to supported chat requests. | Inspect the upstream payload for absent, spoofed, and duplicated operator-message cases. Verify exactly the intended authoritative content is injected. |
| **6. Concurrent request quotas — complete** | Atomic request admission with permanent attempt charging, durable exhaustion, and no completion-time refunds. | Race more requests than the remaining allowance; upstream receives no more requests than permitted. Exercise rejection and upstream-failure paths. |
| **7. Streaming and resource bounds — complete** | Incremental SSE forwarding, client-disconnect handling, connect/first-byte/idle/overall timeouts, and an in-flight limit with `503` retry guidance. | Observe the first SSE chunk before the response completes. Exercise stalls, disconnects, saturation, and upstream failures without hidden retries. |
| **8. Token usage accounting — complete** | Extract usage from ordinary and streaming responses; persist request records and reconcile reservations on every terminal path. Keep unknown usage distinguishable from zero. | Reconcile known mock usage correctly; exercise missing usage, broken streams, and restart with outstanding requests. |
| **9. Hard token-budget enforcement — complete** | Atomically escrow available tokens, narrow to conservative text-prompt and generation bounds before forwarding, and reconcile known or unknown spending exactly once. | Concurrent reservations cannot exceed the job budget. Known usage releases unused escrow; missing usage and restart retain it without fabricating reported usage. |
| **10. Body-policy checks** | Configurable secret-pattern blocking, advisory prompt-injection flags, and redacted audit reasons. | Fake secrets are blocked before forwarding; benign bodies pass; advisory matches are recorded without blocking. Bodies and credentials remain absent from logs. |
| **11. Remaining endpoint support** | Add embeddings and model listing individually, with endpoint-specific validation, accounting, and allowed methods. | Exercise each endpoint end-to-end. Chat prompt transformation never touches embeddings or model-list requests. |
| **12. Operational readiness** | Complete structured logs, Prometheus metrics, per-key usage aggregates, deployment configuration, and operator documentation. Implement spend reporting only with an explicit pricing model. | Run a staging scenario covering issuance, streaming, exhaustion, revocation, and restart; verify the resulting logs and metrics contain no secrets or request bodies. |

For every increment, update the relevant specification details and keep regression tests for consumer-visible boundaries and failure cases.

Steps 1 through 9 are implemented as the HTTPS-only `rustgate` service and separate loopback-only HTTP `mock-upstream` executable. See [the implemented service contract](DESIGN.md#implemented-service-steps-1-through-9) for required TLS/security configuration, issuance, lifecycle and proxy commands, prompt transformation, request charging, streaming deadlines and resource limits, hard text-token budgets and upstream compatibility requirements, accounting and restart recovery, persistence, fixture controls, and capture-API safety limits.

Step 7 verification (historical): Clippy passed with warnings denied; both binaries built. Live HTTPS checks observed the first SSE chunk at 0.048 seconds and completion at 0.915 seconds. A held stream saturated the configured single slot: another attempt received `503` with `Retry-After: 1` without reaching upstream; disconnect released capacity. Delayed first bytes returned `504`, idle and overall deadlines truncated committed SSE without a fabricated `[DONE]`, and a stalled incoming JSON upload returned `504`. A stalled upstream TLS handshake returned `504` at 1.012 seconds with exactly one TCP connection. Upstream `503` status/body/retry guidance passed through; the main mock scenario recorded exactly six expected captures with no hidden retries, using only the configured upstream credential and injected authoritative prompt. Regressions additionally cover actual HTTP disconnects before and after first-byte commitment, unpolled downstream backpressure, active streams that cannot reset the overall deadline, sanitized broken-stream errors, capacity recovery, configuration bounds/precedence, and permanent quota charging.

PR #9 review fix: blocking admission retains its in-flight permit until the worker finishes, including when the caller disconnects or times out. Both queued-admission regressions fail before the fix and pass afterward. Live HTTPS checks hold a SQLite write lock, cancel admission by timeout and disconnect, and observe immediate `503` retry guidance for new attempts until the lock is released. Each abandoned admission charges once after release, capacity recovers, and no abandoned request reaches upstream.

OpenCode compatibility fix: the mock now selects SSE from literal `"stream": true` when no explicit fixture mode is supplied, rather than returning JSON to a streaming client. A failing-before/passing-after regression covers body-selected responses, explicit mode precedence, content, finish reason, and the SSE terminator. Real OpenCode 1.19.4 completes through HTTPS RustGate without query options, returning `Hello from mock.` with finish reason `stop`. A live body-selected stream also delivers its first event before delayed completion.

Step 8 verification: live HTTPS JSON and SSE calls each persist usage `(5, 3, 8)`, with the first SSE event at 0.045 seconds and completion at 0.412 seconds. An upstream failure records unknown usage (`NULL`); a forbidden local route records known zero. Killing the service with a pending delayed request and restarting records `interrupted`, preserves previously known totals, and keeps the original token usable. Repeated restart leaves finalized accounting unchanged. A competing service fails its database ownership lock without interrupting live work; a crash releases the lock for recovery. The final live database has seven charged attempts and 24 known tokens. Regression coverage includes successful missing/zero/malformed usage, fragmented and oversized SSE, broken streams before/after usage, timeout/disconnect/cancelled-admission reconciliation, terminal-job accounting, reservation release, migration/overflow rollback, and concurrent idempotent finalization. A failing-before/passing-after regression also prevents loss of a complete first-chunk usage report when the client disconnects before the relay is first polled.

PR #11 review fixes: ownership now uses a persistent canonical-path `.lock` sidecar held by shared `Store` state through the last blocking worker, rather than an async-main-local lock on SQLite's data file. Committed responses signal EOF/error before awaiting reconciliation, without releasing their in-flight permit early. Before-fix HTTPS checks reproduced a one-second idle timeout still blocked after 1.506 seconds under a SQLite writer lock, and ownership becoming acquirable during shutdown while its worker was still alive. After-fix HTTPS checks observe the transport error at 1.018 seconds with the record still pending and another attempt receiving `503`; a replacement process is refused during shutdown. Releasing the writer lock persists the known 8-token report before exit; subsequent startup preserves it, and SQLite data bytes remain unlocked by ownership. Regressions cover idle/overall deadlines under contention, worker/clone ownership lifetime, restart recovery exclusion, sidecar/data separation, and canonical path aliases. Verification ran on Linux; Windows runtime execution was unavailable.

PR #11 follow-up fixes: pre-commit upstream failures and first-byte timeouts now return `502`/`504` without waiting for SQLite, retaining the permit and terminal outcome in a directly scheduled blocking worker. Usage extraction now rejects array-shaped envelopes/reports without allocating ignored response-content trees. Before-fix HTTPS checks recorded five tokens for each malformed JSON/SSE array case and left a one-second first-byte timeout blocked after 1.510 seconds under a SQLite writer lock. After-fix checks store all four malformed cases as `NULL`, preserve the valid five-token named-object report, and return `504` at 1.002 seconds while accounting remains pending and another attempt receives `503`. Shutdown retains ownership and the intended `timeout` outcome until the writer lock is released. Regressions additionally cover pre-first-byte transport errors, first-byte timeout contention, malformed SSE before/after valid usage, and background finalization across immediate runtime shutdown.

PR #11 cancellation review: complete SSE snapshots are copied into the cancellation guard after both first and later chunks, before any subsequent await. Finalizer destruction also persists usage if runtime shutdown discards a queued blocking closure. Failing-before/passing-after regressions cover first/later complete reports and rejected shutdown workers; boundary coverage retains the latest cumulative report once, preserves it across partial reports, and leaves incomplete usage unknown. An executable smoke scenario using the public router and a real loopback upstream cancels runtimes with streams still open and persists `cancelled` records with 8 and 13 known tokens. Additional provider-behavior regressions request usage when options are omitted, override client `false` while preserving sibling options, and charge invalid non-object options as known zero without forwarding. The executable smoke also verifies the captured options, two completed 8-token requests, and a rejected zero-token request.

Step 9 live HTTPS verification: a held request reserves all 1024 available tokens; seven concurrent attempts receive `429` without request charges or upstream calls. Known usage settles to 8 tokens and releases 1016. A successful missing-usage response retains 1024 in `tokens_unreported`, keeps report columns `NULL`, and durably exhausts the job. SSE preserves an explicit `max_completion_tokens` cap with `n = 2` and settles known usage; malformed input refunds token escrow while retaining its request charge. Killing the service with a pending 1000-token reservation and restarting records `interrupted`, retains 1000 as unreported spending, and denies further work; a second restart leaves counters unchanged. Text-only fail-closed validation, Unicode/escaped prompt accounting, generation/choice boundaries, independent SQLite connection races, idempotent release, lifecycle, and migration rollback have permanent regression coverage.

Step 9 final checks: all 131 regression tests pass; Clippy passes with warnings denied; both executables build. The live HTTPS scenario above exercises the compiled service against a real loopback upstream.

## Release checkpoints

- **After step 5:** useful local integration slice; not ready for build containers because quotas and streaming guarantees are incomplete.
- **After step 9:** core authenticated, streaming, quota-controlled proxy.
- **After step 12:** candidate for deployment against the complete specification.

Before connecting real build containers, verify the external network boundary: containers cannot reach the upstream directly, and the proxy's configured egress restrictions actually hold. Application tests cannot prove those firewall guarantees.

## Deferred extensions

Keep Vault integration, optional debugging-body storage, risk scoring, and escalation of advisory scans out of the initial roadmap. They are separable extensions, not prerequisites for the core proxy.
